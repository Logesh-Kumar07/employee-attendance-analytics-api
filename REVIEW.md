# Starter code review

| # | Where | Confirmed defect and symptom | Fix and regression coverage |
|---|---|---|---|
| 1 | Mongo client setup | A local URI and database name were silently hard-coded as fallbacks; environment configuration was not mandatory as required. | Read `MONGO_URI`/`MONGO_DB`, load optional `.env` without overriding real environment variables, and allow unconfigured startup with 503 database readiness. Checked by health tests and startup behavior. |
| 2 | `health()` | It always returned 200 without contacting MongoDB, including when MongoDB was down. | Ping MongoDB and return 503 on failure; exercised by [test_health_returns_503_when_mongodb_ping_fails](tests/test_main.py). |
| 3 | Startup | No required indexes were created, so uniqueness and query performance were not guaranteed. | Create the unique and supporting indexes idempotently on startup; index names are asserted by [test_startup_indexes_and_health](tests/test_main.py). |
| 4 | `EmployeeIn` / `create_employee()` | Employee formats, calendar dates, and equal shift endpoints were not validated. | Add contract-matched Pydantic validation; invalid code and equal shifts are covered by [test_employee_validation_and_pagination_limits](tests/test_main.py). |
| 5 | `create_employee()` | `datetime.now()` produced a naive timestamp, making the stored instant depend on an implicit timezone. | Store aware UTC and expose epoch milliseconds; response shape is checked in [test_employee_create_duplicate_and_filtered_pagination](tests/test_main.py). |
| 6 | `create_employee()` | Check-then-insert allowed concurrent duplicate employee codes. | Enforce unique `emp_code` in MongoDB and map duplicate-key errors to 409; sequential and parallel cases are in [test_employee_create_duplicate_and_filtered_pagination](tests/test_main.py) and [test_concurrent_employee_creates_and_punch_ins_have_single_winner](tests/test_main.py). |
| 7 | `list_employees()` | The department filter used truthiness, and `total` counted the entire collection instead of the filtered set. | Apply exact filters, including an empty string, and count with the same query; covered by [test_employee_create_duplicate_and_filtered_pagination](tests/test_main.py). |
| 8 | `list_employees()` | `skip = page * page_size` skipped the first page. | Use `(page - 1) * page_size`; the second-page result is asserted in [test_employee_create_duplicate_and_filtered_pagination](tests/test_main.py). |
| 9 | `list_employees()` | Results were not sorted by `emp_code`, and page bounds were unchecked. | Sort ascending and enforce page ≥ 1 / page_size 1–100; covered by [test_employee_create_duplicate_and_filtered_pagination](tests/test_main.py) and [test_employee_validation_and_pagination_limits](tests/test_main.py). |
| 10 | `compute_late_minutes()` | Replacing the input timestamp's clock fields used the host timezone/date; the strict 10-minute boundary (09:40:01) was also lost by flooring before applying the grace rule. | Compare whole-second instants on the IST shift date and apply `elapsed > 600` before flooring; exact boundaries are tested in [test_late_grace_and_work_overtime_half_day_boundaries](tests/test_main.py). |
| 11 | `compute_work_hours()` | Built-in `round()` uses ties-to-even and floating-point arithmetic, contrary to half-up contract rounding. | Use decimal half-up rounding; 4.49/4.50 half-day boundaries are tested in [test_late_grace_and_work_overtime_half_day_boundaries](tests/test_main.py). |
| 12 | `compute_overtime()` | It resolved overnight shift end on the wrong day and counted any positive extra minute, even below the 30-minute minimum. | Resolve shift end from the record date and require at least 30 whole minutes; threshold and overnight cases are covered by [test_late_grace_and_work_overtime_half_day_boundaries](tests/test_main.py) and [test_overnight_date_punch_out_and_overtime](tests/test_main.py). |
| 13 | `punch_in()` timestamp/date handling | `datetime.fromtimestamp()` used the host timezone; falsy timestamps defaulted to now, and seconds, floats, strings, out-of-range values, and subsecond truncation were not correctly handled. | Strictly validate epoch milliseconds, truncate to seconds, and convert through UTC/IST; covered by [test_punch_in_late_rounding_timestamp_validation_and_duplicate](tests/test_main.py). |
| 14 | `punch_in()` | Unknown employees caused an attribute/key error, and arbitrary statuses could create unsupported records. | Return 404 for unknown employees and restrict creation to presence statuses; covered by [test_punch_in_late_rounding_timestamp_validation_and_duplicate](tests/test_main.py). |
| 15 | `punch_in()` | Duplicate detection was check-then-insert, without a unique natural-key index, so simultaneous punches could both succeed. | Use one insert protected by unique `(emp_code, date)`; the concurrent single-winner assertion is in [test_concurrent_employee_creates_and_punch_ins_have_single_winner](tests/test_main.py). |
| 16 | `punch_in()` response | It returned an `id` copied from MongoDB `_id`, which the contract excludes. | Serialize only documented fields; checked in [test_punch_in_late_rounding_timestamp_validation_and_duplicate](tests/test_main.py). |
| 17 | `list_attendance()` | It loaded and sorted the whole collection in Python, making 100k records expensive; tie ordering by `emp_code` was missing. | Filter, sort, count, skip, and limit in MongoDB using the documented two-key sort; exercised by [test_punch_out_and_attendance_filter_sort_pagination](tests/test_main.py). |
| 18 | `list_attendance()` | It returned an `id` field, accepted malformed/reversed date ranges and arbitrary statuses, and did not enforce pagination bounds. | Return schema-only records and validate dates, statuses, and page parameters; covered by [test_punch_out_and_attendance_filter_sort_pagination](tests/test_main.py). |
| 19 | Missing contract routes | Punch-out, regularization, analytics, and explain routes were absent and returned 404. | Implement all routes. Mongo-backed result and explain tests are in [test_mongo_integration.py](tests/test_mongo_integration.py); they were skipped locally because no MongoDB URI/server was available. |

**Reviewed and retained:** the starter's page and page-size defaults (1 and 20), employee/punch-in HTTP creation status (201), and sample collection names matched the contract. The index guarantee and all behavior around those defaults still required implementation or correction as listed above.
